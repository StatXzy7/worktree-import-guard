# 0.1.0 release notes — draft, not published

Catch tests that pass while importing a different checkout. Install into your project's existing
pytest environment, select import names and source directories, and run one check.

The first candidate provides PASS / FAIL / UNKNOWN results with expected and observed paths,
actionable explanations, a disposable two-worktree demo, and optional JSON schema v2 reports.
Pytest's result is shown separately. Native nonzero pytest exits remain unchanged.

## Enable this quick start only after 0.1.0 is available on PyPI

From the project root, using its existing environment (`.venv` is an example):

```sh
".venv/bin/python" -m pip install worktree-import-guard==0.1.0
".venv/bin/wt-import" --expect demo_pkg=src/demo_pkg -- -q
```

PowerShell:

```powershell
& ".venv\Scripts\python.exe" -m pip install worktree-import-guard==0.1.0
& ".venv\Scripts\wt-import.exe" --expect demo_pkg=src/demo_pkg -- -q
```

Replace the example environment and package mapping. Installation may adjust pytest dependencies.
For flat layouts use `--expect demo_pkg=demo_pkg`. During an incident, use the installed script
before syncing or reinstalling. Candidate-wheel smokes simulate this path; they are not evidence
of a successful PyPI download.

## Scope

Only explicitly selected packages and observed sources in one supported pytest process are checked.
UNKNOWN is not a pass. No automatic repairs, coverage proof, commit-content verification, complete
xdist/child-process tracing or sandboxing. Multi-root namespaces remain unsupported.
